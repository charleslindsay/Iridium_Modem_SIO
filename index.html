BeaverCube Flight Computer

A CubeSat flight computer with novel fault detection, isolation and response (FDIR) system. Supports a high data rate imaging payload plus standardized bus and power interfaces for the BeaverCube 3U CubeSat mission.

Mission Overview

Objective
  • Measure and track sea-surface temperature and color through infrared and visual spectrum imaging of coastal environments
CubeSat Requirements
  • Survive 90 days in low Earth orbit (LEO)
  • Support a primary and backup radio, antenna control board, electrical power system board, thermal control board, attitude control board, GPS, electrospray propulsion module and imaging payload
Communication & Data Handling
  • Recover autonomously from software faults and non-destructive hardware upsets from ionizing radiation impact
  • Provide an onboard inertial measurement unit (IMU) and real-time clock (RTC)
  • Provide data storage for payload image storage
  • Run flight software to coordinate systems and data transfer

Design Challenges

Mechanical Constraint

Board must sit within the standard 3U CubeSat chassis stack. It will interface with the main power and communications bus through a standardized PC/104 header.

Radiation Problem
  • Flash memory corruption: SD cards will corrupt while in LEO due to ionizing radiation. This causes unexpected read/write faults, which can prevent the flight computer from booting flight software and running operations.
  • Voltage regulator failure: DC-DC converters are sensitive to ionizing radiation and can fail unpredictably, cutting power to all systems.
Solutions
  • Dual watchdogs: In the event of a non-destructive single event latch-up that halts the flight computer, both the external electrical power system board or onboard hardware watchdog can trigger a reboot.
  • Remote reboot: The primary radio can toggle which compute module is running with a command from ground, regardless of the flight computer's state.
  • FDIR system: Two Raspberry Pi compute modules connected to four SD cards plus the FDIR system create a single-fault tolerant system that can autonomously recover from unexpected shutdowns.
05

Testing

Initial board checkout evaluating voltage ripple on the main power rail. Power resistors simulate passive loading. An Iwatsu SS-6122 100 MHz analog oscilloscope is used with probe input set to AC coupling.

Logic analyzer test diagnosed missing USB net connections. PCB re-work involved cutting traces on the prototype board and soldering thin wires to pads smaller than an 0402 footprint.
